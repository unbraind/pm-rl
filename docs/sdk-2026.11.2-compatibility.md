# SDK 2026.11.2 compatibility

The three failures introduced by upgrading the development SDK from 2026.10.27
to 2026.11.2 come from two changes released in 2026.10.30. The installed SDK
changelog identifies GH-1617 (history presentation order) and GH-1614 (literal
typed mutation inputs). Neither requires changing canonical tracker documents.

## Retained generation evidence

In `dist/sdk/query/history.js`, 2026.10.27 projects `selectedHistory` directly.
2026.11.2's `buildHistoryProjection` defaults compact/provenance reads to
`newest_first` and reverses the selected rows. Durable `index`/`version`
coordinates still identify the same historical documents. On a two-revision
tracker, the compact row indices change from `[1, 2]` to `[2, 1]`.

The frozen main producer at `26650e3` scans compact history in physical order.
That changes the `at` field in its `PolicyCardEvidence`, which participates in
card identity, even when the domain digest is identical. Instrumenting its
failure under 2026.11.2 gives this shared citation:

```json
{
  "id": "rl-loop-seed",
  "retained_at": "2",
  "fresh_at": "4",
  "retained_digest": "b85fa082ef4ecc452d4d742c94bc728f4017cf90ad2fd609d291529748c9941b",
  "fresh_digest": "b85fa082ef4ecc452d4d742c94bc728f4017cf90ad2fd609d291529748c9941b"
}
```

The candidate's promotion changes its own digest and adds the approval citation
as expected. The seed citation's different coordinate incorrectly prevents the
legacy producer from recognizing that transition. The failure is unrelated to
locks, metadata files, canonical field changes, or a changed history entry shape.

Production on this branch already routes history consumers through
`orderedHistoryEntries` in `index.ts`, validates certified durable coordinates,
and sorts them ascending. `firstDecisionSnapshot` therefore retains the first
semantic revision independently of SDK presentation. `policy-card.ts` hashes
pm-rl domain content, excluding SDK presentation/bookkeeping metadata. No
migration or relaxed drift comparison is needed.

The compatibility test now gives the immutable legacy producer its exact
2026.10.27 SDK through a development-only npm alias. Its fifteen native trackers
are then read and resumed by current pm-rl with SDK 2026.11.2. Historical cards
and identities remain unchanged. After successful resume, appending exactly one
ASCII byte to a cited Run body must make another resume refuse with
`loop_generation_drift`. SDK read-back must retain that exact one-byte edit.
The existing seeded history permutations additionally
exercise both durable versions and legacy physical indices. Replacing the
ascending sort with physical array order is a negative control for this corpus.

## Legacy envelopes and peer mutation

In `dist/sdk/lifecycle/update.js`, `normalizeLegacyNoneUpdateOptions` previously
converted scalar `none` values to `unset`. It now skips normalization for literal
SDK mutation input; `dist/sdk/runtime-input.js` marks typed SDK calls as literal.
`dist/core/item/parent-reference-policy.js` then rejects `parent: "none"` as a
placeholder. Clearing fields requires `unset: ["parent", ...]`.

The legacy process-envelope test, packed process-publication probe, and
training-influence peer injection used the old sentinel. They now use the SDK's
explicit unset form. A search of production TypeScript mutation calls, including
the shared creation helpers and scripts, found no other placeholder field clears
using `none`, `null`, `-`, or an empty string. Domain JSON nulls, textual refusal
messages, display fallbacks, and Docker's `network_mode: "none"` are not SDK
field-clear options.

The peer-title failure is not a history/message order change. The injected
`peer.update` rejected its parent argument before it could write the title.
The test accepted the propagated expected SDK error and subsequently observed
the original title. The test retains the `Peer succeeded` assertion and now
also requires every injected mutation to finish. Every native boundary remains
covered; changing its unset back to `parent: "none"` must fail.

These are extension-absorbable SDK behavior changes. No incompatible canonical
item/history field was found, so no upstream defect report is proposed.

  one-byte `loop_generation_drift` control (one test, zero skips).
- The two mutation regressions pass through `pm test --run --progress`, using
  a snapshot with no inherited PM context (two tests, zero skips).
- A scratch checkout with physical history order restored and both sentinel
  updates restored fails all three original tests. The upgrade reader refuses
  with `loop_generation_drift`; the other failures reproduce the parent
  rejection and unchanged peer title respectively.
