# Bounded causal language-model adapter

[`pm-rl-upe0`](../.agents/pm/features/pm-rl-upe0.toon), a child of
[`pm-rl-apvf`](../.agents/pm/epics/pm-rl-apvf.toon), implements criterion 2 in
[RECURSIVE_TRAINING.md](../RECURSIVE_TRAINING.md). It runs through the existing
controller, controller lease, replay, Hoeffding gate and transactional promotion
path. The external Compose adapter shares that controller and the durable process contract described below.

## Model and learning contract

`trainer: "lm"` selects a decoder-only transformer with one or two pre-norm blocks,
single-head causal attention, tanh feed-forward layers and learned token and
positional embeddings. Width is at most 48; vocabulary is the declared alphabet
(up to 37 symbols) plus BOS, SEP and EOS. Strings have one declared length, 1–6.
Parameters are Float32Array; numerical activations and accumulated gradients use
Float64Array to make the hand-written backward pass checkable. All operations
are TypeScript on CPU; the adapter needs no Python, native kernel or GPU.

The base is regenerated by 60 deterministic Adam steps over 24 copy examples
cycled from the **declared training strings only**, with label-smoothed
cross-entropy. It ships as code, without a binary weight blob. Held-out strings
never enter pretraining, collection or a gradient. The seed adapter has random
low-rank input factors and zero output factors, so its policy equals the base.
Both model and self-authored synthetic data must explicitly declare MIT.

RL changes only rank-1–4 factors on Q/V and the output head. Two-layer models
share the Q/V adapter across their blocks; gradients accumulate across both.
Collection samples complete answers autoregressively from the currently promoted
adapter. The target is an alphabet successor cipher: `01234` maps to `12340`.
The exact verifier pays half per-position accuracy plus half for a fully correct
string. REINFORCE uses the observed **sequence** reward minus the batch mean,
with an exact softmax KL gradient anchored to the frozen base and global L2
clipping. Multiple fit steps descend the fixed collected-batch surrogate; the
next generation collects a fresh batch only after promotion.

Greedy held-out exact-match is measured before and after fitting; a regression
refuses promotion. Teacher-forced target probabilities supply a separately
identified reward proxy for the shared training-gap/improvement checks. Its
positional term is a proxy, not the exact autoregressive expected positional
reward. Independent seeded sampled completions supply the actual bounded
verifier rewards for the existing Hoeffding gate. A proxy increase alone cannot
promote. Repeated decisions make this an adaptive validation set; a separate
final benchmark is needed for unbiased generalization claims.

Both example identities and SHA-256 string-content identities must be unique
and disjoint across training and held-out sets. Differently named copies refuse
before collection. Rejected candidates never become the collection policy.

## Limits and durable evidence

The programme must declare `limits.max_parameters`, `max_checkpoint_bytes`,
`max_steps`, `max_wall_seconds`, `model_license` and `dataset_license`.
The parameter cap counts the frozen base **and** adapter. The optimizer cap
reserves all 60 pretraining steps plus `max_generations * fit_steps` before
execution. Checkpoint bytes cover the actual canonical UTF-8 artifact. The wall
allowance bounds each CPU phase (base regeneration, collection, fit/evaluation),
with checks between optimizer batches, collection samples and evaluation
episodes. A single bounded kernel completes before the next clock check;
this synchronous adapter does not provide hard OS preemption. PM I/O, setup and
replay are separate from the numerical phase clock. The loop also retains its
generation, collection-sample and approved-promotion bounds.

Distinct refusals include `lm_limit_parameters_exceeded`,
`lm_limit_checkpoint_bytes`, `lm_limit_steps_exceeded`, `lm_limit_wall_seconds`,
`lm_invalid_license`, `lm_dataset_overlap` and `lm_nonfinite_tensor`. Configuration
refusals are commented on the supplied approval Decision; execution refusals are
commented on the seed. Completed candidates record `checkpoint_limit_exceeded`
or `wall_limit_exceeded` in their generation refusal. Oversized candidates retain
their receipt but are not materialized as checkpoint files. No refusal grants a budget
increase.

Artifacts live under tracker-relative
`runtime/pm-rl/artifacts/<sha256>.json`, outside the replaceable installed
extension directory. Uninstalling and reinstalling the package preserves them.
Their digest hashes exactly the
canonical stored bytes, binding format, architecture, base digest and every
adapter tensor. Existing files are verified and never overwritten; missing or
corrupt artifacts refuse. Generation receipts retain before/after digests,
canonical tensors, artifact path/bytes, full parameter count, reserved optimizer
steps, actual parameter-delta L2 norm, surrogate loss before/after, greedy
accuracy, proxy scores, sampled evaluation reward and wall milliseconds.
Collection Run notes retain the complete per-sample reward curve. Across the
ordered generations those receipts are the reward/evaluation curves.
Replay verifies collection, tensors, losses, scores, resource metadata and
artifact bytes before advancing. `rlLoopStatus(client, id, pmRoot)` requires the
tracker root for artifact verification when using the SDK directly.

## Run a synthetic programme

Install the packed package in a scratch pm project and use the full shipped
[example](../examples/loop-lm.json). Authorize only its bounded promotions:

```sh
pm create Decision "Allow four synthetic LM promotions" --id lm-approval \
  --body '```json
{"permitted_promotions":4}
```'
pm rl loop run lm-demo --file node_modules/pm-rl/examples/loop-lm.json --approval lm-approval --json
pm rl loop status lm-demo --json
```

The example declares one layer, width 16, FFN 32, rank 4, eight vocabulary symbols
and nine learned positions: **2,560 frozen + 352 trainable = 2,912 parameters**.
Its caps are 4,096 parameters, 65,536 checkpoint bytes, 256 optimizer steps and
60 seconds per CPU phase. It declares at most four generations, 64 collection
samples per generation and 400 total collection samples. Each policy receives
1,600 sampled held-out evaluation episodes per generation (separate from the
collection budget). The approved promotion Decision remains an independent cap.

## Verification

`test/lm.test.ts` finite-differences **every scalar of every parameter tensor**
in a two-layer model, including all six nonzero LoRA factors, and asserts each
tensor's relative L2 error is below 1e-3. It separately checks the REINFORCE+KL
surrogate on every adapter scalar, seed determinism, frozen base invariance,
causality, serialization and failure paths. `test/lm-loop.test.ts` covers durable
integration, lineage, budgets, replay, cancellation and corrupted evidence.
`test/lm-cli.test.ts` installs a packed artifact, launches the real CLI for three
generations, verifies disk hashes and successor use, preserves every checkpoint
through a real package uninstall/reinstall, checks regression and
contamination refusals, and enforces a 20-second command budget.

The performance child runs without V8 coverage instrumentation, which materially
slows the numerical kernels; the same authored TypeScript implementation remains
covered by numerical and durable integration tests. No coverage source or
threshold is excluded to obtain the performance measurement.

```sh
npm ci
npm run typecheck
node --test test/lm.test.ts test/lm-loop.test.ts test/lm-cli.test.ts
npm run release:check
bun run release:check
bun test --timeout 120000 test/lm.test.ts test/lm-loop.test.ts test/lm-cli.test.ts
```

The release gate inventories every authored source under the repository root,
including operational scripts, and enforces exact statement/line/branch/function
thresholds of 100/100/100/100, docstrings, lint, zero jscpd duplication, identity
and production dependency audits, packed contents and generated changelog.
`bun run release:check` runs the repository's existing Node-based quality gates;
the direct Bun tests separately exercise the adapter and packed CLI with Bun.


## External Compose trainer, 2026-10-16

[pm-rl-whrd](../.agents/pm/features/pm-rl-whrd.toon) extends the existing
[process contract](process-trainer.md) with `adapter.kind: "compose-lm"`.
It uses the same job identity, SDK owner fences, atomic reservation, staged
completion validation, cancellation, settlement and recovery. The container
performs the real TypeScript REINFORCE update; the controller evaluates its
candidate on held-out data and uses the existing promotion gate.

Build from the source checkout with:

```sh
docker build --tag pm-rl-lm-trainer --file lm-trainer.Dockerfile .
docker image inspect pm-rl-lm-trainer --format '{{.Id}}'
```

Put that immutable image ID in the programme's adapter before execution:

```json
{
  "kind": "compose-lm",
  "image": "sha256:<local immutable image ID>",
  "memory_bytes": 268435456,
  "cpus": 1,
  "allowance": {
    "training_steps": 6,
    "wall_ms": 60000,
    "storage_bytes": 2097152,
    "compute_units": 60000,
    "tokens": 100000
  }
}
```

The programme retains the existing explicit MIT model/data licences, 4,096
parameter cap, 65,536-byte checkpoint cap and 256-step total optimizer bound.
The measured programme uses two generations, 64 collected completions each,
1,600 held-out episodes per policy and the unchanged confidence/improvement/gap
gates. An independently created approval Decision permits two promotions and
supplies `resource_budget` covering both complete per-job allowances. The
controller never expands that Decision. Adapter step and wall allowances must
agree with the LM programme; image, CPU and memory changes alter its identity.

The Dockerfile pins Node's base by SHA-256 and executes a TypeScript entrypoint
as a non-root user. Compose also sets a non-root numeric UID/GID, read-only root,
dropped capabilities, no privilege escalation, no network, no ports, no host
environment forwarding and a PID cap. `mem_limit` and `memswap_limit` enforce
the declared memory ceiling with no extra swap; `cpus` limits CPU scheduling.
The image installs only locked package dependencies during build. Training uses
`--pull never` and has no network. It mounts only job staging; its serialized
training request and Compose configuration are additionally mounted read-only.
The request contains frozen tensors, source adapter, training strings and the
actual collected completions/rewards. Held-out examples and tracker access are
absent. Frozen weights are restored without repeating pretraining.

The completion receipt binds canonical checkpoint bytes, source policy,
training/dataset identities, losses, parameter delta and real tensors. It reports
actual optimizer steps, fit CPU milliseconds, target tokens optimized across
those steps, peak resident memory, wall milliseconds and checkpoint bytes.
The controller additionally measures startup-through-completion wall time and
all retained staging bytes. Surrogate diagnostic passes are included in CPU and
wall use; `tokens` counts optimized collected target tokens. Bootstrap and
protocol processing are outside the fit CPU interval. Cleanup retains a compact
`compose-stop.json` containing daemon-observed memory/CPU configuration,
network/user isolation, exit code and OOM status. Unknown failed-job consumption
settles conservatively against the whole reservation and retained evidence.

`test/lm-compose.test.ts` exercises the same trainer through real stdin/stdout
and Docker Compose. Its Docker availability gate is identical to the existing
Compose suite: skip only when `docker compose version` fails; a failed daemon,
build or drill with an available CLI is a failure. All authored sources retain
the existing exact 100/100/100/100 coverage thresholds.


Real-container drills retained attributable evidence:

- A controller SIGKILL after checkpoint/completion fsync and before the PM receipt
  commit recovered byte-identical artifacts, promoted once and settled the
  original six-step charge, with exactly one launch marker.
- Cancellation after the real fit's first progress event killed only the owned
  container, retained its read-only input and events and settled `process_cancelled`.
- A corrupted real fit checkpoint failed digest validation; a real allocation
  beyond a 192 MiB container ceiling recorded Docker `oom_killed: true`; a
  1,000-step real LM fit crossed its 15-second wall allowance after its progress
  event. Both refused promotion.
  Each failure retained staging, settled its reservation and collected no successor.
- Two real controllers contended for one programme: one received
  `loop_controller_active`; the winner launched one container and created one
  settled reservation. Resume adopted the same completed generation.

Behavioural revert proofs used isolated source snapshots with unchanged tests:
restoring only `executePendingGeneration` from the pre-feature implementation
failed the two-generation test because external job receipts were absent (0/1);
forcing LM jobs through the launch branch of `executeReservedProcessJob` instead
of staged recovery failed the SIGKILL test on exclusive existing input evidence
(0/1); removing only the measured memory/token refusal in
`validateLmProcessCheckpoint` failed its invalid-use regression (0/1).
The restored snapshot passed all three cases, with zero skips. These proofs
neither removed the live container memory ceiling nor altered the package worktree.
